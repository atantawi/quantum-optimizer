G3 (GATE) F(B) = 0 at chi = nu reproduces qopt's ray

  F(B)=0 is exactly qopt's SECOND stationarity equation, dT/dm2 = -chi*beta_2.
  qopt solves the RATIO of that and its m1 twin, which eliminates chi. So the
  two must agree when, and only when, chi is the station's own shadow price
  nu = |dT/dm1|/beta_1 = |dT/dm2|/beta_2.

G4 (GATE) the budget C cannot reach the answer
======================================================================================
  The docx takes C = c_FJ from the optimization loop, but C enters L only as an
  additive constant, so it cancels from dL/dS_2 and appears nowhere in F. The
  root is therefore bit-for-bit independent of C over any range at all.

  (F's signature has no C argument to vary -- that IS the finding.)
  root at the one chi supplied: B = 1.063992175701365

  And the constraint the docx imposes has no content either: with S_1 and C
  both taken from step 1, S_2 = (C - c_1 S_1)/c_2 is already determined, so
  min over S_2 has zero degrees of freedom. G5 measures that.
  VERDICT: PASS - C is not an argument of F: the budget from step 1 cannot influence S_2

G5 (GATE) at qopt's converged solutions the constraint is an identity
======================================================================================
  spend = S_1*(c_1 + c_2 r*/r) = c_1 S_1 + c_2 S_2 holds for EVERY r*, so
  using the constraint to pin chi instead cannot move the ray: any r* is
  self-consistent. Measured at all three QCSC fixed points.

  The two are the same NUMBER but not the same float expression --
  (S*alloc_cost - c_1*S)/c_2 subtracts and divides where S*(r*/r) multiplies --
  so agreement is to within an ulp, not bit-for-bit. The ulp column is the
  measurement; do not restate it as exact equality.

G7 the only multiplier the loop has is not the one F needs
======================================================================================
  eq 21 carries no explicit chi, but implies one. Its stationarity gives
  S_i = gamma_i/mu_i + sqrt(w_i zeta_i/(nu c_i mu_i)), hence
      nu_net = w*zeta*mu / (alloc_cost*(S*mu - gamma)^2),
  equal across stations at eq 21's solution -- which is the check that it has
  been recovered correctly. But nu_net prices the ZETA-LINEARIZED surrogate
  w*zeta/(S*mu - gamma), which matches T in value at the fixed point and not
  in derivative. So it is not the station's nu.

G8 (GATE) the kink r* = 1, which a smooth F = 0 cannot represent
======================================================================================
  t_ul's T_bot kinks at m1 = m2, where the correct condition is one-sided
  (derivation section 6). classical_dominant's answer IS that kink. The docx's
  F pairs the two rates' one-sided derivatives from opposite branches, so its
  root steps past the kink into the region where its own T is wrong.
